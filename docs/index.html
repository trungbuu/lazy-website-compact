02 · Quy trình

Từ tài liệu đến bản bàn giao

Luồng ngắn cho người mới, nhưng vẫn giữ những điểm kiểm tra cần thiết để website không dừng ở mức minh họa.

1

Chọn nguồn

Gửi đường dẫn file trên máy hoặc link Google Drive cụ thể. Nêu file nào là bản chuẩn khi có nhiều phiên bản.

2

Chốt mục tiêu

Xác định ai sẽ xem, thông điệp chính, bằng chứng được phép công bố và CTA dẫn tới đâu.

3

Dựng bản chạy

Tạo cấu trúc, nội dung, responsive, metadata và các trạng thái cần thiết. Giữ stack nhỏ nhất đủ dùng.

4

Kiểm và giao

Kiểm link, tài sản, nhiều cỡ màn hình, CTA và form. Bàn giao lệnh chạy cùng phần còn cần xác nhận.

Nguồn A

File trên máy

Phù hợp khi tài liệu, ảnh và logo đã nằm trong một thư mục dự án. Chỉ rõ đường dẫn và phạm vi agent được đọc.

Nguồn B

Google Drive

Gửi link file hoặc thư mục cụ thể và quyền đọc phù hợp. Website sau khi build không phụ thuộc người xem phải đăng nhập Drive.

03 · Hướng dẫn

Dùng skill theo từng bước

Bạn không cần viết brief dài. Bốn thông tin đúng quan trọng hơn một tài liệu nhiều trang nhưng chưa rõ ai xem và họ cần làm gì.

Đi nhanh tới 1. Cài skill 2. Gửi nguồn 3. Viết yêu cầu 4. Nghiệm thu

1. Cài skill từ GitHub

Clone cả repository rồi đặt nguyên thư mục vào vùng skills mà môi trường agent hỗ trợ. Không chỉ lấy riêng file SKILL.md, vì hướng dẫn nhận nguồn và script kiểm HTML cũng được dùng.

Terminal
git clone https://github.com/trungbuu/lazy-website-compact.git

2. Gửi nguồn đúng phạm vi

  • File trên máy: gửi đường dẫn cụ thể tới thư mục, file nội dung và tài sản nhận diện.
  • Google Drive: gửi link file hoặc thư mục và nói rõ tài liệu nào là nguồn chính.
  • Nêu dữ liệu không được công bố, ai duyệt nội dung và CTA thật.
  • Nếu giá, số liệu hoặc chính sách mâu thuẫn, skill sẽ dừng ở điểm đó để xin bản chuẩn.
Google Drive chỉ là nguồn biên tập. Bản website phải hoạt động độc lập, không bắt khách truy cập đăng nhập Drive để xem nội dung công khai.

3. Dùng câu lệnh mẫu

Thay nội dung trong ngoặc vuông. Nếu chưa có phong cách, bỏ dòng đó và để skill đề xuất một hướng phù hợp với nội dung.

4. Nghiệm thu trước khi publish

  • Tiêu đề đầu trang nói rõ bạn làm gì và dành cho ai.
  • Không còn văn bản giữ chỗ, nút rỗng, đường dẫn chết hoặc nội dung chưa xác minh.
  • Trang không tràn ngang ở mobile, menu và focus bàn phím hoạt động.
  • CTA dẫn đúng email, số điện thoại, lịch hẹn hoặc endpoint đã thống nhất.
  • Nếu có form, gửi thử đầu cuối và xác nhận nơi nhận thật.
  • Phần bàn giao nêu lệnh chạy, build, kết quả kiểm và giới hạn còn lại.
